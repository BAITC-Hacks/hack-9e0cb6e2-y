# Сопоставление транскрипта и говорящих

`autoprotocol.pipeline.align` объединяет результаты двух локальных CLI. Оно не
загружает модели, не использует сеть и не меняет исходные JSON.

```powershell
.\.venv\Scripts\python.exe -m autoprotocol.pipeline.align data/smoke/meeting-1-full-stt.json data/smoke/meeting-1-full-diarization.json --output data/smoke/meeting-1-aligned.json --text-output data/smoke/meeting-1-aligned.txt
```

## Правила

- Входы должны относиться к одной записи и общей временной шкале. Проверяются
  длительности (допуск 50 мс), интервалы, порядок слов и уникальность source ID.
  Одинаковая длительность не доказывает идентичность аудио: CLI пока не имеет
  общего audio_id/hash. Пользователь выбирает два результата одной записи.
- Сопоставление выполняется по интервалам каждого слова, а не всего STT-сегмента.
- Используются обычные интервалы pyannote: exclusive-вариант скрывает перекрытия.
- Слово получает speaker_id, только если с ним пересекается один говорящий,
  покрывающий не менее 60% длительности слова. Это инженерный порог, не вероятность
  правильности; он ещё не настроен на размеченном корпусе.
- Любое пересечение слова с несколькими говорящими оставляет speaker_id=null.
  Одновременная речь получает `overlapping_speech`, последовательная смена
  говорящего внутри слова — `speaker_boundary`.
- Недостаточное покрытие — `insufficient_coverage`; отсутствие интервала —
  `no_speaker_evidence`; нулевая длительность — `zero_duration`.
  Соседний говорящий не подставляется для заполнения пробелов.
- Повторяющиеся интервалы одного говорящего объединяются перед подсчётом покрытия.
- Если таймкодов слов нет, сохраняется исходный текст с неизвестным говорящим
  и флагом `missing_word_timestamps`. Расхождение текста сегмента и слов получает
  `word_text_mismatch`; исходная версия сохраняется, а в TXT выводится отдельно.

Последовательные слова с одинаковыми говорящим и флагами группируются внутри
исходного сегмента. Смена говорящего или статуса проверки создаёт новый фрагмент.
Нулевые интервалы сохраняются только для спорных слов: их время не выдумывается.
При построении плеера такие места следует открывать с небольшим контекстом.

## Формат результата

`source_segments` сохраняет оригинальные STT-сегменты; `segments` содержит
`aligned_*` ID, `source_segment_id`, миллисекунды, текст, speaker_id,
review_flags и исходные слова с source_word_index. Для слова сохраняются
кандидаты и длительность пересечения в миллисекундах.
Имена не выводятся из номера говорящего; `speaker_names_confirmed=false`.
ID стабильны при повторном запуске с теми же входами, но могут измениться после
повторного inference. Ручной редактор пока не реализован.

## Проверка на записи №1

- Длительность: 274.25 с, четыре метки говорящих из диаризации.
- 45 исходных сегментов → 68 фрагментов.
- Все 573 слова сохранены; 544 слова получили speaker_id, 29 оставлены без него.
- 20 фрагментов требуют проверки. Эти числа характеризуют правила сопоставления,
  а не измеренную точность диаризации.
- Тесты покрывают смену говорящего, перекрытия, пробелы, повторные интервалы,
  нулевые таймкоды, отсутствие слов, расхождения текста и ошибочные входные интервалы.

TXT — черновик для просмотра, не требуемый ТЗ экспорт протокола в DOCX/PDF.
Web-загрузка, очередь, имена, редактор, поручения и экспорт остаются следующими фазами.
