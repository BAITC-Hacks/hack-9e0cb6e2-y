# Фаза 5 — ручная проверка поручений и итогов

Добавлен редактор сохранённого анализа. Текст поручения, ответственный, исходный
срок и его тип, статус, текст и категория саммари доступны для исправления.
Пункты можно подтвердить по записи или исключить без удаления. Изменение поля
снимает галочку проверки в UI. Кнопка сохранения отдельная от транскрипта.

## Данные и защита правок

- SQLite v5: analysis_reviews и analysis_revisions, привязанные к analysis_id.
- Исходный вывод LLM и evidence не меняются; доступны исходные поля каждого пункта.
- Нормализация срока повторяется после правки, только по дате встречи и
  поддерживаемым формулировкам. Неизвестный ответственный остаётся null.
- Атомарное сохранение с expected_revision; конфликт вкладок — 409 без потери
  текста формы. Фоновый опрос не перерисовывает несохранённый черновик.
- Устаревший анализ нельзя редактировать. Новый анализ не наследует ручные
  исправления старого; прежняя история остаётся в БД и API.
- Исключение обратимо, сохраняется и отражается в истории. Экспорт ещё не готов.

Подробные контракты — [MANUAL_REVIEW.md](MANUAL_REVIEW.md).

## Фактические проверки

На Windows 10 / Python 3.11:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\ruff.exe check src tests scripts
.\.venv\Scripts\ruff.exe format --check src tests scripts
node --check src/autoprotocol/web/static/app.js
git diff --check
```

90 тестов прошли. Ruff и проверка JavaScript — без ошибок.
Есть предупреждение Starlette о транспорте httpx в TestClient.
Новые проверки покрывают неизменность исходного вывода и цитат, сохранение после
повторной инициализации, историю, исключение/восстановление, очистку срока,
Unicode RU/KK, no-op сохранение, конкурентные запросы 200/409, атомарный отказ
от чужого пункта, запрет подмены evidence, Origin, неготовый и устаревший анализ.
Миграция с прежней схемы сохраняет встречи; новые таблицы создаются повторяемо.

## Проверка браузера

`scripts/check_review_browser.py` создаёт временную БД и синтетический результат,
поднимает отдельный сервер на свободном localhost-порту и использует headless Chrome.
Реальные записи и пользовательская БД не меняются; LLM и STT не запускаются.
Аудио теста — тишина, поэтому проверяется запуск плеера, а не содержание речи.

Для воспроизведения нужен установленный Chrome и отдельный тестовый Playwright:

```powershell
uv run --with playwright==1.63.0 python scripts/check_review_browser.py --channel chrome
```

Также предусмотрен `--channel msedge` для установленного Edge; он в этом прогоне
не проверялся. Chromium требует отдельной установки браузера Playwright.
Playwright не нужен для обычного запуска приложения и не добавлен к runtime-зависимостям.

Пройдено в Chrome:

1. Правка задачи, ответственного и срока; подтверждение, сохранение и перезагрузка.
2. Сравнение с исходным ответом модели, история старых/новых значений.
3. Кнопка источника запускает HTML audio и переходит к реплике.
4. Фоновое обновление сохраняет несохранённый ввод.
5. Две вкладки: первая сохраняет, вторая получает 409 с сохранением своего текста.
6. Загрузка актуальной версии, исключение саммари и сохранность отметки после reload.
7. Изменение и сохранение транскрипта через UI делает анализ недоступным для правок.
8. Экран 390 px без горизонтального переполнения; исправлен перенос длинного заголовка.
9. Ошибок JavaScript нет. Скриншоты desktop/mobile в data/browser-review-check/;
   изображения просмотрены, поля и подписи читаемы.

## Что осталось

Следующая фаза — DOCX из сохранённой версии с учётом excluded, reviewed, исходных
сроков и источников. Создание новых поручений/итогов и редактирование источников
пока не реализованы. Автослияния конфликтов нет; история старых анализов доступна
через API, в интерфейсе — история выбранного анализа.

Этот прогон не доказывает качество распознавания или извлечения на RU/KK/mixed,
не заменяет полный сценарий новой записи с экспортом и не является проверкой
изолированного от внешней сети окружения.
