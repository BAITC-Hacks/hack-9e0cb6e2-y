# Фаза 7 — проверка полного сценария и устойчивости

Дата: 23.09.2026. Статус: частичная приёмка. Новый полный проход с настоящими
локальными моделями завершён, измерение WER/CER и воспроизводимые проверки добавлены.

## Что проверено на аудиозаписи

Вход — 17,312 секунды синтетической русской речи Microsoft Irina из
`tests/fixtures/ru_smoke.txt`. Использован существующий WAV, но вся обработка
выполнена заново через HTTP в отдельной новой БД: прежние транскрипты и ответы
моделей не подставлялись. Эталонный текст не передавался в модель для распознавания
или анализа. Личные записи и основная БД приложения в этом прогоне не использовались.

Профиль: Windows 10, Python 3.11, CPU; faster-whisper-small int8,
pyannote community-1; Qwen3-4B Q4_K_M, llama.cpp b11124, 4 потока, контекст 8192.
Версии/хеши моделей — в [MODELS.md](MODELS.md) и manifest-файлах проекта.

## Точность распознавания

[Переносимый манифест](evaluation/ru-smoke-20260923-manifest.json),
[исходная гипотеза до правок](evaluation/ru-smoke-20260923-hypothesis.json) и
[расчёт метрик](evaluation/ru-smoke-20260923-metrics.json) содержат только
синтетический материал. SHA-256 исходного WAV и полного результата сохранены
для проверки происхождения данных.

| Материал | Объём | WER | CER | Статус |
|---|---|---:|---:|---|
| RU, один синтетический голос | 22 слова, 143 символа после нормализации | 0% | 0% | Измерено |
| KK, реальные голоса | Нет размеченной выборки | — | — | Не оценено |
| Mixed RU/KK | Нет размеченной выборки | — | — | Не оценено |

Нормализация: Unicode NFKC, нижний регистр, ё → е, пунктуация заменяется пробелами,
повторные пробелы объединяются; казахские буквы сохраняются. WER использует слова,
CER — символы без пробелов. Расстояние Левенштейна считает вставки, удаления и замены;
усреднение по корпусу взвешивается числом эталонных слов/символов. Пустой эталон
или отсутствие файла не превращаются в нулевую ошибку.

Нулевые ошибки на одном синтетическом голосе не доказывают качество настоящих
совещаний. DER и corpus precision/recall поручений не измерены. Четыре текстовых
сценария извлечения описаны отдельно в [отчёте фазы 6](PHASE_6_REPORT.md).

## Проверка сетевых обращений

Для теста добавлен опциональный Python guard: разрешены числовые loopback-адреса,
внешние TCP/UDP и DNS блокируются в стандартных socket API; в версии 2 учтён
Windows asyncio Proactor. Проверочные запросы действительно отклоняются,
локальный HTTP и наследование окружения дочерним Python работают. Журналы содержат
версии, PID и счётчики, без адресов, токенов, аудио и текста встречи.

Первый WAV-прогон выполнялся во время доработки guard: в журналах есть версии 1 и 2.
Он не считается проверкой только окончательной версии. Наблюдение за сокетами
процессов каждые 0,5 с не обнаружило внешних соединений; ошибок доступа при
наблюдении — 0. Среди замеченных процессов — Python и llama-server; короткие
запуски FFmpeg могли закончиться между выборками.

Повторный MP4-прогон прошёл с окончательным guard v2: семь активных Python-журналов,
все версии равны 2, некорректных журналов и заблокированных попыток — 0.
Наблюдение также не выявило внешних соединений и ошибок доступа; замечен ffprobe.
Guard отклонял намеренные TCP/DNS/UDP-пробы в отдельном тесте, но в самом прогоне
модели не вызвали блокировку. Эти два вида проверок учитываются отдельно.

**Полной изоляции ОС не было.** Native-код llama.cpp, FFmpeg и C-расширений может
обойти Python guard, а выборка сокетов может пропустить короткое соединение.
Поэтому закрытый контур требует отдельного прогона в среде с запретом внешней сети
на уровне ОС. Сеть компьютера и глобальный firewall при этой проверке не менялись.
Подробности: [инструкция guard](../scripts/offline_guard/USAGE.md).

## Воспроизведение

Модели и зависимости должны быть подготовлены по [руководству](DETAILED_GUIDE.md).
Команды выполняются из корня репозитория. Для каждого полного прогона нужна новая
папка вывода; существующая папка не перезаписывается. Скрипт рассчитан на известную
синтетическую реплику с поручением, а не на произвольную запись.

```powershell
# Синтетическое аудио, без личных данных
.\scripts\synthesize_smoke.ps1

# Новые API, worker, БД и настоящее выполнение всех моделей
.\.venv\Scripts\python.exe scripts/check_end_to_end.py --output-dir data/acceptance/my-run --offline-guard

# Необязательный повтор с MP4; выходной файл должен отсутствовать
ffmpeg -nostdin -hide_banner -loglevel error -f lavfi -i color=c=black:s=320x240:r=10 -i data/smoke/ru.wav -map 0:v:0 -map 1:a:0 -c:v libx264 -preset ultrafast -c:a aac -shortest -n data/smoke/ru-video.mp4
.\.venv\Scripts\python.exe scripts/check_end_to_end.py --audio data/smoke/ru-video.mp4 --output-dir data/acceptance/my-video-run --offline-guard

# Отдельные проверки блокировки TCP/DNS/UDP
.\.venv\Scripts\python.exe scripts/check_offline_guard.py --log-dir data/acceptance/my-probe

# Пересчёт опубликованного синтетического результата без запуска ML
.\.venv\Scripts\python.exe scripts/evaluate_transcription.py --manifest docs/evaluation/ru-smoke-20260923-manifest.json --output data/acceptance/recomputed-metrics.json

# Та же оценка со строгой проверкой покрытия: ожидается exit 1, пока KK/mixed отсутствуют
.\.venv\Scripts\python.exe scripts/evaluate_transcription.py --manifest docs/evaluation/ru-smoke-20260923-manifest.json --output data/acceptance/strict-metrics.json --require-complete
```

`report.json` содержит проверки, время, память и сводку сети. Рядом сохраняются
исходный транскрипт, анализ и два DOCX. Рабочие артефакты находятся в игнорируемой
`data/acceptance/`. В Git публикуются только скрипты, синтетические текстовые
фикстуры и отчёты. Успех обычного CLI расчёта означает завершение расчёта;
он не означает прохождение порога качества.

## Исправления и оставшаяся приёмка

Автоматические проверки: **158 pytest-тестов прошли**; Ruff, форматирование и
`git diff --check` без ошибок. Остаётся предупреждение Starlette об устаревшем
httpx-транспорте TestClient. 55 новых тестов покрывают тишину и сообщения по
этапам, расчёт метрик с неполными данными, сетевую блокировку и валидацию журналов.

Перед публикацией создана отдельная копия только закоммиченных файлов через
`git archive`. В ней выполнен `uv sync --frozen --offline` в новой venv из локального
кеша: установлены базовые и dev-зависимости. В этой копии повторно прошли все
158 тестов, Ruff и форматирование; страница, `/health/live` и `/openapi.json`
ответили 200 через TestClient с loopback Host. Импорт проверен именно из новой
копии, а не из исходного рабочего каталога. Это проверка комплектности кода и
чистой базовой среды; загрузка ML-моделей в пустой кеш и полный первый запуск
установщика на другом компьютере этим не подтверждаются.

Worker останавливает обработку, если STT не распознал речь, и показывает понятную
подсказку. Сбой подготовки, STT, диаризации или сопоставления теперь объясняется
отдельно; команды, пути записей и вывод модели в ошибке не раскрываются.

Следующий этап: согласованный размеченный набор RU/KK/mixed с несколькими людьми,
DER и полнота извлечения, длинные записи, прогон при запрете сети на уровне ОС и
чистая установка по README. `/health/ready` сохраняет 503 до завершения этой
приёмки; рабочие загрузка, редактор, анализ и DOCX доступны.
