# Фаза 4: локальные поручения и саммари

Реализован экспериментальный сквозной путь: сохранённый транскрипт → очередь
анализа → локальная Qwen3 → проверенный по схеме JSON → карточки поручений и итогов
с цитатами и таймкодами. Это черновик, требующий проверки человеком, а не принятая
корпусная оценка извлечения. Редактирование карточек и экспорт ещё впереди.

## Подготовка и ресурсы

Основной профиль: Windows x64, CPU, четыре потока, Qwen3-4B Q4_K_M,
llama.cpp b11124 (`0.4.1-dev`, commit `1a679828f`). Изначальный кандидат 8B заменён
на 4B при 4,58 ГиБ свободной RAM. Это выбор по ресурсам, не доказательство
равного качества моделей. Для уменьшения памяти отключена перепаковка весов
(`--no-repack`), batch=256, ubatch=128. Память runtime измеряется каждые 250 мс;
метрики записываются в `metadata.runtime_peak_rss_mib`. Это RSS процесса, не общая
память приложения и не доказанный минимальный объём RAM компьютера.

## Контракт и хранение

`POST /api/meetings/{id}/analysis` принимает JSON с `source_digest` и
`expected_revision` из GET результата. Сервер транзакционно делает снимок текущей
сохранённой версии с метаданными встречи, участниками и репликами. Несохранённый
текст браузера не отправляется на анализ. Конфликт версии — 409; неподготовленные
локальные файлы LLM — 503. Доступ к записи другого origin отклоняется.

Миграция v4 добавляет `analyses`: meeting_id, digest, revision, input_json,
status, owner, lease_until, attempt, error, result_json. Старые встречи и ручные
правки сохраняются. Результат анализа содержит фактические поля поручений и саммари
в JSON; отдельных редактируемых ActionItem/SummaryItem-таблиц ещё нет.

Статусы анализа: `queued → processing → ready/failed`, независимо от статуса
распознавания. Повторный POST той же версии не дублирует обработку; после failed
он явно запрашивает повтор. Автовосстановление после истечения lease допускает
две попытки; обычная ошибка сразу становится failed. Старый owner не может
опубликовать результат или продлить чужую lease. Heartbeat и общий worker
сериализуют задачи распознавания и LLM, чтобы не держать тяжёлые модели одновременно.
При обновлении кода нужно перезапустить launcher; старый worker не знает о новой очереди.

`GET /api/meetings/{id}/analysis` возвращает статус, сохранённый результат,
его revision/source_digest и `stale`. Если человек изменил транскрипт во время
или после анализа, прежний результат остаётся доступен с пометкой устаревания.
Исходный snapshot не меняется, новая обработка запускается явно. Файлы попыток
лежат в `data/analyses/<id>/<owner>/`; опубликованный результат также в SQLite.

## Модель, источники и сроки

Промпт трактует транскрипт как данные. Модель не получает инструментов и адресов
сервисов. Adapter запускает свой llama-server на `127.0.0.1` с отдельным API-ключом,
локальным файлом модели, `--offline`, без web UI и логирования. Запросы обходят
прокси, перенаправления запрещены; сервер останавливается по завершении/ошибке.
Проверка с физическим отключением внешней сети пока не выполнена.

Применяются JSON-schema generation и независимая Pydantic-проверка. Допускаются
первая попытка и максимум две повторные; невалидный/обрезанный ответ не публикуется.
В технические логи не выводится содержимое реплик или ответов модели.

Поручение хранит действие, исполнителя nullable, исходный срок nullable, тип срока,
статус proposed/agreed/changed/cancelled, источник постановки и массив evidence.
Говорящий постановки вычисляется из источника и не заменяет исполнителя.
Имя исполнителя и срок должны дословно присутствовать в подтверждающих цитатах;
неявные назначения через местоимения пока могут остаться null. Нет автоматического
объединения одинаковых имён с Participant или проверки личности исполнителя.

У каждого поручения и пункта саммари есть существующий segment_id и непустая
точная подстрока реплики. К evidence добавляются исходные времена и speaker_id.
Модель должна сохранять начальную постановку и поздние изменения, объединять
переговоры об одной задаче. Валидатор отклоняет идентичные дубликаты текста задачи;
смысловое объединение разных формулировок и обнаружение противоречий не гарантированы.
Саммари разделено на fact/decision/action/question.

Наличие точной цитаты **не доказывает смысловую верность** вывода. Все пункты имеют
`requires_review=true`; интерфейс не объявляет их подтверждёнными. Ссылки позволяют
прослушать источник, а в актуальной версии — перейти к соответствующей реплике.

Календарные значения вычисляются кодом, не свободным ответом LLM:

- явная дата ISO `YYYY-MM-DD` (в том числе с «до»/«к»);
- «сегодня», «завтра», «послезавтра», «через N дней» только при дате встречи;
- «на следующей неделе» — интервал понедельник–воскресенье при дате встречи;
- остальные сроки и условия сохраняются исходным текстом с пометкой проверки.

Без даты встречи относительный срок не привязывается к сегодняшней дате.
Сложные конфликты, «до пятницы», падежи/словесные числительные и казахские
формулировки ещё не нормализуются. Часовой пояс хранится во входе; нормализация
работает с календарными датами без часов. Отсутствующий срок — null/unspecified.

Контекст ограничен 8192 токенами: не более 5700 токенов реально отформатированного
входа (включая схему/инструкцию) и 2200 токенов ответа. Есть предварительный лимит
40 000 символов snapshot. Превышение отклоняется, тихого обрезания текста нет.
Разбиение длинного анализа на части с объединением поручений пока не реализовано.

## Проверки

77 обычных тестов проходят без скачивания и запуска тяжёлых моделей. Для этого
этапа добавлены проверки источников/выдуманных полей, дат, повторов JSON, границы
контекста, отсутствующих весов, привязки snapshot, устаревания, API, дедупликации
запросов, конкурентного захвата, восстановления lease и взаимного исключения STT/LLM.
Ruff, форматирование и синтаксис JavaScript проверены.

Отдельный реальный LLM-прогон `tests/fixtures/extraction_ru.json`: 1 поручение Ерлану,
2 точные цитаты, «завтра» при 2026-09-23 → 2026-09-24; 71,406 секунды от отправки
промпта, 292 токена ответа, первая попытка. Загрузка модели в это время не включена.

В `tests/fixtures/extraction_cases.json` входы отделены от ожидаемых результатов.
Оценка передаёт модели только `meeting`, без `expected`:

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_extraction.py
```

Результаты и метрики сохраняются в `data/extraction-evaluation.json`. Это небольшие
синтетические **текстовые** кейсы, не подтверждение качества ASR/диаризации или
корпусной точности поручений. Первоначальная инструкция v1 прошла изменение срока
и пример без поручений с цитатой атаки; на кейсе без срока ответ был отклонён после
повторных попыток. Инструкция v2 явно уточняет null для отсутствующего срока и
добавляет безопасные подсказки валидатора при повторе.

После уточнения v2 случай без срока прошёл с первой попытки за 60,125 секунды
на первоначальном профиле runtime. Дополнительно выполнен HTTP POST анализа
существующего транскрипта синтетической аудиозаписи: queued → processing → ready,
1 поручение и 1 пункт саммари, 160,08 секунды целиком, две попытки JSON.
Исполнитель — Ерлан; срок «до пятницы» сохранён текстом без придуманной даты.
Распознавание аудио в этом прогоне не повторялось: использован ранее полученный
настоящим STT/диаризацией результат. Артефакт проверки локально:
`data/analysis-http-check.json`. Эти времена получены до отключения перепаковки.

Итоговый повтор всех трёх кейсов на инструкции **v2** и экономном CPU-профиле:

| Синтетический случай | Проверенный результат | Время анализа | Попытки |
|---|---|---|---|
| Изменение срока | Одно поручение Ерлану, итоговый срок 2026-10-15, исходная и изменяющая реплики сохранены | 134,015 с | 1 |
| Нет поручений + процитированная атака | Поручения не созданы | 44,641 с | 1 |
| Срок не назначен | Одно поручение Ерлану, срок null | 38,328 с | 1 |

Модель загружалась один раз за 2,094 с; второй и третий запросы использовали кеш
общей части промпта. Время таблицы не включает загрузку. Максимальный наблюдаемый
RSS runtime за этот прогон — 3626,5 МиБ при опросе каждые 250 мс. Это измерения
на коротких входах, а не гарантия скорости/памяти для полного контекста.
Полные результаты только этих синтетических примеров:
[extraction-evaluation.json](extraction-evaluation.json).

После перезапуска общего launcher GET анализа ранее обработанной синтетической
аудиозаписи вернул точно тот же сохранённый JSON. Проверены наличие элементов
интерфейса, синтаксис JS и 21 блок PowerShell в README. Интерактивные клики по
новым карточкам в браузере в этой фазе отдельно не проверялись.

Полная визуальная/интерактивная браузерная приёмка нового блока, KK/mixed-корпус,
сложные отмены/изменения исполнителя, precision/recall и длинные записи остаются
непроверенными. Фаза 4 в полном объёме ещё не принята.
