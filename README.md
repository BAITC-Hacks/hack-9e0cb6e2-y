# Автопротоколирование совещаний

Проект для HackAlem AI по автоматическому созданию протоколов совещаний и фиксации поручений. Система должна принимать запись встречи, локально распознавать речь, разделять реплики участников и формировать проверяемый протокол с ответственными и сроками.

## Проблема

Ручное ведение протокола занимает время секретаря и создаёт риск потерять или исказить договорённости. Особенно критичны поручения: кто должен выполнить задачу, что именно требуется сделать и к какому сроку.

Цель проекта — сократить ручную работу и сделать каждое извлечённое поручение проверяемым по исходным репликам встречи.

## Планируемый сценарий

1. Пользователь загружает аудио- или видеозапись совещания.
2. Система локально подготавливает аудио и распознаёт русскую, казахскую и смешанную речь.
3. Диаризация разделяет запись на реплики разных говорящих.
4. Пользователь при необходимости сопоставляет идентификаторы говорящих с именами участников.
5. Модель выделяет решения, поручения, ответственных, сроки и открытые вопросы.
6. Пользователь проверяет результат и подтверждающие реплики.
7. Готовый протокол экспортируется в PDF и/или DOCX.

## Обязательный результат MVP

- транскрипт встречи с временными метками;
- разделение реплик по говорящим;
- поддержка русского, казахского и переключения между языками;
- краткое саммари и список принятых решений;
- структурированные поручения: действие, ответственный и срок;
- подтверждающая цитата для каждого поручения;
- экспорт протокола в файл;
- обработка записей без передачи аудио и текста во внешние облачные API.

## Принципы

- **Закрытый контур.** Распознавание речи, диаризация и смысловой анализ выполняются локально или на self-hosted компонентах.
- **Проверяемость.** Система не должна выдавать предположение за факт; поручения сопровождаются ссылкой на исходную реплику.
- **Контроль пользователя.** Неуверенные имена, сроки и соответствия говорящих можно проверить и исправить до экспорта.
- **Честная оценка качества.** Поддержка языков подтверждается тестовыми записями, а не только заявленными возможностями моделей.

## Планируемый конвейер

```text
Запись встречи
    -> подготовка аудио
    -> локальное распознавание речи
    -> диаризация
    -> сопоставление говорящих
    -> извлечение решений и поручений
    -> проверка пользователем
    -> экспорт протокола
```

## Статус

Работает путь: загрузка записи → SQLite-очередь → отдельный worker → локальные
Whisper и pyannote → черновой транскрипт в интерфейсе с аудиоплеером и таймкодами.
Встречи и результаты сохраняются после перезапуска. Предел: 250 МБ и 10 минут.
Редактор имён, поручения, саммари и экспорт пока не реализованы.
[Результаты ML-прогонов](docs/PHASE_1_REPORT.md) и [проверка web-конвейера](docs/PHASE_2_REPORT.md).
Добавлено [объединение транскрипта с говорящими](docs/ALIGNMENT.md) по таймкодам слов,
с сохранением источников и пометками спорных мест.

Подробный технический план и критерии приёмки находятся в [AUTOPROTOCOL_PROMPT.md](AUTOPROTOCOL_PROMPT.md).

## Стек и план реализации

Основной стек: Python 3.11, FastAPI, Pydantic, Jinja2, обычный JavaScript,
SQLite и локальное файловое хранилище. Длительная обработка выполняется
отдельным Python worker. Docker и Node для запуска не требуются.

Кандидаты для ML: faster-whisper, pyannote community-1, Qwen3 GGUF через llama.cpp.
Первый формат экспорта — DOCX. Русский STT проверен на примерах; качество KK/mixed
и точность говорящих ещё не измерены на размеченном корпусе.

## Установка каркаса на Windows

Нужны Python 3.11 и доступ к сети только для установки зависимостей.
Команды выполняются в корне репозитория:

```powershell
python -m pip install uv==0.8.22
.\scripts\setup.ps1
```

Установка использует `uv.lock` и создаёт `.env`, если файла ещё нет.
Если политика PowerShell запрещает запуск скриптов, эквивалентные команды:

```powershell
uv sync --frozen
Copy-Item .env.example .env  # только если .env ещё нет
```

## Обычный запуск

Для обработки записей сначала установить ML-профили и веса (нужен интернет):

```powershell
.\scripts\setup.ps1 -WithML
winget install --id Gyan.FFmpeg --exact --source winget
.\.venv\Scripts\python.exe scripts/prepare_stt.py
.\.venv\Scripts\hf.exe auth login
.\.venv\Scripts\python.exe scripts/prepare_diarization.py
```

Для community-1 предварительно принять условия на странице модели; подробнее
в [документации моделей](docs/MODELS.md). После установки FFmpeg открыть новый
терминал. На текущем компьютере веса и зависимости уже подготовлены.

После установки одна команда, без скачивания пакетов и моделей:

```powershell
.\scripts\run.ps1
```

Открыть http://127.0.0.1:8000. Остановить через Ctrl+C.
Скрипт запускает сервер и worker, останавливая дочерние процессы при завершении.
Без PowerShell-скрипта: `.\.venv\Scripts\python.exe -m autoprotocol.launch`.
На Linux после `uv sync --frozen --extra stt --extra diarization` используется
`.venv/bin/python -m autoprotocol.launch` (ML на Linux здесь не проверялся).
Если порт занят, задайте `$env:AUTOPROTOCOL_PORT='8011'` перед запуском.

`/health/live` возвращает 200 для работающего web-сервера; `/health/ready`
пока возвращает 503, поскольку полный протокол с поручениями и экспортом ещё
не реализован. Это не мешает загрузке и получению чернового транскрипта.
Данные SQLite создаются в `data/`; `.env`, записи, веса и результаты не коммитятся.
Стартовая страница не использует внешние CDN. Сервер доступен только с этого компьютера.

## Проверки каркаса

```powershell
.\.venv\Scripts\ruff.exe check src tests scripts
.\.venv\Scripts\ruff.exe format --check src tests scripts
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m autoprotocol.diagnostics
```

Диагностика не скачивает веса и не проверяет качество моделей. Тесты проверяют
загрузку, очередь, восстановление, сопоставление говорящих и сохранность данных.
Реальный HTTP-проход с ML проверен отдельно; экспорт и полная offline-приёмка ещё нет.
