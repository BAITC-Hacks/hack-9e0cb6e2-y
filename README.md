# Автопротоколирование совещаний

Проект для HackAlem AI по автоматическому созданию протоколов совещаний и фиксации поручений. Система должна принимать запись встречи, локально распознавать речь, разделять реплики участников и формировать проверяемый протокол с ответственными и сроками.

## Проблема

Ручное ведение протокола занимает время секретаря и создаёт риск потерять или исказить договорённости. Особенно критичны поручения: кто должен выполнить задачу, что именно требуется сделать и к какому сроку.

Цель проекта — сократить ручную работу и сделать каждое извлечённое поручение проверяемым по исходным репликам встречи.

## Планируемый сценарий

1. Пользователь загружает аудио- или видеозапись совещания.
2. Система локально подготавливает аудио и распознаёт русскую, казахскую и смешанную речь.
3. Диаризация разделяет запись на реплики разных говорящих.
4. Пользователь при необходимости сопоставляет идентификаторы говорящих с именами участников.
5. Модель выделяет решения, поручения, ответственных, сроки и открытые вопросы.
6. Пользователь проверяет результат и подтверждающие реплики.
7. Готовый протокол экспортируется в PDF и/или DOCX.

## Обязательный результат MVP

- транскрипт встречи с временными метками;
- разделение реплик по говорящим;
- поддержка русского, казахского и переключения между языками;
- краткое саммари и список принятых решений;
- структурированные поручения: действие, ответственный и срок;
- подтверждающая цитата для каждого поручения;
- экспорт протокола в файл;
- обработка записей без передачи аудио и текста во внешние облачные API.

## Принципы

- **Закрытый контур.** Распознавание речи, диаризация и смысловой анализ выполняются локально или на self-hosted компонентах.
- **Проверяемость.** Система не должна выдавать предположение за факт; поручения сопровождаются ссылкой на исходную реплику.
- **Контроль пользователя.** Неуверенные имена, сроки и соответствия говорящих можно проверить и исправить до экспорта.
- **Честная оценка качества.** Поддержка языков подтверждается тестовыми записями, а не только заявленными возможностями моделей.

## Планируемый конвейер

```text
Запись встречи
    -> подготовка аудио
    -> локальное распознавание речи
    -> диаризация
    -> сопоставление говорящих
    -> извлечение решений и поручений
    -> проверка пользователем
    -> экспорт протокола
```

## Ближайшие этапы

1. Проверить доступное окружение и выбрать локальные модели.
2. Реализовать обработку записи и получить транскрипт с временными метками.
3. Добавить диаризацию и ручное сопоставление участников.
4. Реализовать извлечение поручений с подтверждающими репликами.
5. Собрать интерфейс проверки и экспорт протокола.
6. Провести сквозные тесты на русской, казахской и смешанной речи.
