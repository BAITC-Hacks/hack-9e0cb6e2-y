# JazAI — локальное автопротоколирование совещаний

Проект для HackAlem AI. JazAI принимает запись совещания, локально распознаёт речь и разделяет говорящих. Результат — черновой транскрипт с таймкодами, аудиоплеером и пометками спорных мест.

**Работающий сценарий текущей версии: загрузка → транскрипт с говорящими → сохранение ручных исправлений → локальный анализ поручений и саммари с источниками.** Анализ выдаёт черновик для проверки. Экспорт DOCX/PDF ещё не реализован.

## Возможности и ограничения

| Возможность | Текущий статус |
|---|---|
| Web-загрузка файла | Реализована; по умолчанию до 250 МиБ и 10 минут |
| Локальное распознавание | faster-whisper, multilingual small, CPU int8 |
| Русская речь | Проверена на реальной и синтетической записи; корпусная точность не измерена |
| Казахская и смешанная речь | Требование проекта; качество ещё не проверено |
| Разделение говорящих | pyannote community-1; метки вида `SPEAKER_00` |
| Текст с говорящими и таймкодами | Реализован; неоднозначные места отмечаются |
| Аудиоплеер и переход к реплике | Реализованы в интерфейсе; HTTP Range проверен |
| Сохранение встреч и очереди | SQLite и локальные файлы; данные переживают перезапуск |
| Имена участников и ручные исправления | Подтверждение имён, правка текста/говорящего, отметка проверки и история версий |
| Поручения, ответственные, сроки и саммари | Локальная Qwen3-4B, проверка точности цитат, источники с таймкодами; все выводы требуют проверки |
| Экспорт DOCX/PDF | Пока не реализован |
| Teams / Zoom / Google Meet | Интеграции пока нет; текущий вход — файл |

`SPEAKER_00` — условный голос в пределах одной записи, а не установленное имя человека. Количество и границы говорящих могут быть определены неверно. Когда сопоставление неоднозначно, говорящий остаётся неизвестным.

## Требования к компьютеру

**Проверенный основной путь — Windows 10 Pro x64, PowerShell и Python 3.11.9.** Проект требует **Python 3.11** (`>=3.11,<3.12`); Python 3.12/3.13 не входит в поддержанный диапазон этой версии.

| Компонент | Требование |
|---|---|
| Python | 3.11 x64, проверка: `py -3.11 --version` |
| Git | Для клонирования репозитория |
| uv | 0.8.22 для установки зависимостей из `uv.lock` |
| FFmpeg и ffprobe | Оба должны быть доступны в терминале; проверена сборка Gyan 9.0.2 |
| RAM | Прогоны выполнены на компьютере с 16 ГБ; минимальный объём отдельно не установлен |
| GPU | Не требуется; текущий web-worker работает на CPU |
| Диск | STT/диаризация — около 519 МБ, LLM — ещё 2,5 ГБ и runtime; дополнительно нужны несколько ГБ под библиотеки, кеш и записи |
| Интернет | Нужен для первоначальной установки, входа Hugging Face и скачивания весов |
| Hugging Face | Собственный аккаунт с доступом к модели community-1 |
| Браузер | Современный браузер с JavaScript и поддержкой WAV |

**Ollama, Docker, Node.js, Redis, PostgreSQL и ключ облачной LLM для запуска не нужны.** На Linux/macOS полный ML-проход в этом проекте не проверялся; для демонстрации используйте основной Windows-путь.

## Первый запуск на Windows

Подготовьте окружение и модели до демонстрации: время загрузки зависит от сети и компьютера. Не продолжайте следующие шаги, если предыдущая команда завершилась ошибкой.

### 1. Базовые инструменты

Установите [Git для Windows](https://git-scm.com/downloads/win) и [Python 3.11 x64](https://www.python.org/downloads/windows/), если их ещё нет. При установке Python включите Python Launcher (`py`). Откройте **PowerShell**:

```powershell
git --version
py -3.11 --version
```

Вторая команда должна вывести `Python 3.11.x`. Если `py` отсутствует, но `python --version` показывает именно 3.11, можно заменить `py -3.11` на `python` в следующих командах.

Установите uv в выбранный Python:

```powershell
py -3.11 -m pip install uv==0.8.22
py -3.11 -m uv --version
```

Форма `python -m uv` не требует отдельной команды `uv` в PATH. Другие способы установки описаны в [официальной документации uv](https://docs.astral.sh/uv/getting-started/installation/).

Установите FFmpeg:

```powershell
winget install --id Gyan.FFmpeg --exact --source winget
```

**Закройте терминал и откройте новый**, чтобы обновился PATH. Если `winget` недоступен, выберите Windows-сборку на [официальной странице FFmpeg](https://ffmpeg.org/download.html) и добавьте каталог с `ffmpeg.exe` и `ffprobe.exe` в PATH.

Проверьте в новом терминале:

```powershell
ffmpeg -version
ffprobe -version
```

### 2. Копия проекта

Выполните в каталоге, где хотите разместить проект:

```powershell
git clone https://github.com/BAITC-Hacks/hack-9e0cb6e2-y.git
cd hack-9e0cb6e2-y
```

**Все дальнейшие команды выполняются из корня репозитория**, рядом с `pyproject.toml`. Путь к профилю разработчика и его личные файлы не нужны. Если копия уже есть, перейдите в неё вместо повторного клонирования.

### 3. Зависимости и конфигурация

```powershell
py -3.11 -m uv sync --frozen --extra stt --extra diarization
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe --version
```

Создаётся `.venv`, устанавливаются точные версии из `uv.lock`, включая обе ML-группы. Активация окружения не нужна: далее используется его Python по полному относительному пути. Существующий `.env` не перезаписывается.

Если `uv` доступен в PATH и PowerShell разрешает скрипты, эквивалентная установка:

```powershell
.\scripts\setup.ps1 -WithML
```

Для обработки речи нужны **оба** флага `--extra stt --extra diarization`. Обычный `uv sync` или `setup.ps1` без `-WithML` устанавливает базовый профиль и может удалить дополнительные ML-пакеты.

### 4. Модель распознавания речи

```powershell
.\.venv\Scripts\python.exe scripts/prepare_stt.py
```

Скачивается фиксированный revision `Systran/faster-whisper-small` в `models/faster-whisper-small/`. Этот набор публичный; вход обычно не требуется. Основной файл весов занимает около 484 МБ. После скачивания появляется `models/stt-manifest.json` с revision и SHA-256 файлов.

### 5. Доступ к модели диаризации

**Каждому проверяющему нужен доступ на своём аккаунте** — доступ разработчика не передаётся через GitHub.

1. Войдите или зарегистрируйтесь на Hugging Face.
2. Откройте [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1).
3. Прочитайте и примите условия, если согласны; заполните форму. Условия предусматривают передачу авторам email и имени пользователя, а также описывают рассылку.
4. Убедитесь, что появилась надпись **You have been granted access to this model**.

Теперь авторизуйте локальный компьютер:

```powershell
.\.venv\Scripts\hf.exe auth login
```

CLI предложит вход через браузер: откройте выданный адрес, введите показанный код и подтвердите вход **в том же аккаунте**, которому открыт доступ. Дождитесь `Login successful` в терминале.

Если CLI предлагает вход токеном, создайте токен с правами чтения в [настройках Hugging Face](https://huggingface.co/settings/tokens) и вставьте его в интерактивный запрос терминала. Сохранение в Git credentials не требуется. Не добавляйте токен в исходники, README, `.env.example` или сообщения в репозитории.

### 6. Скачать веса диаризации

```powershell
.\.venv\Scripts\python.exe scripts/prepare_diarization.py
```

Фиксированная версия community-1 сохраняется в `models/pyannote-community-1/`, manifest — в `models/diarization-manifest.json`. Выбранные файлы занимают около 33 МБ. Во время обработки используются уже скачанные локальные веса.

Проверьте наличие основных файлов:

```powershell
Test-Path models/faster-whisper-small/model.bin
Test-Path models/faster-whisper-small/tokenizer.json
Test-Path models/pyannote-community-1/config.yaml
Test-Path models/pyannote-community-1/segmentation/pytorch_model.bin
Test-Path models/pyannote-community-1/embedding/pytorch_model.bin
Test-Path models/pyannote-community-1/plda/plda.npz
Test-Path models/pyannote-community-1/plda/xvec_transform.npz
```

Для каждой строки ожидается `True`. Наличие файлов само по себе ещё не доказывает качество inference. Revision, размеры и SHA-256: [Whisper](docs/stt-model-manifest.json), [community-1](docs/diarization-model-manifest.json).

Лицензия выбранных весов Whisper — MIT; community-1 — CC-BY-4.0. Авторы и атрибуция указаны в model card community-1 и README, сохранённых вместе с весами.

### 7. Подготовка модели поручений и саммари

Для анализа используется **Qwen3-4B Q4_K_M** и отдельная Windows x64 CPU-сборка **llama.cpp b11124**. Веса и runtime скачиваются один раз, без передачи записей. Новых Python-пакетов не требуется:

```powershell
.\.venv\Scripts\python.exe scripts/prepare_llm.py
```

Скрипт скачает около 2,5 ГБ весов и архив runtime (~19 МБ), проверит SHA-256, распакует исполняемые файлы в `models/llama-b11124/` и сохранит `models/llm-manifest.json`. Запускайте подготовку до старта приложения. Если задан неработающий локальный прокси, для прямого скачивания можно добавить `--direct`. После обрыва повторите команду: загрузка поддерживает продолжение `.partial` там, где сервер поддерживает Range.

Проверка основных файлов:

```powershell
Test-Path .\models\qwen3-4b\Qwen3-4B-Q4_K_M.gguf
Test-Path .\models\llama-b11124\llama-server.exe
```

Обе строки должны вернуть `True`. Точная модель, сборка, лицензии и ограничения описаны в [фазе 4](docs/PHASE_4_REPORT.md). Этот профиль пока проверяется на небольших русскоязычных примерах; размер модели не является обещанием качества казахской речи.

### 8. Диагностика и запуск

```powershell
.\.venv\Scripts\python.exe -m autoprotocol.diagnostics
```

Ожидаются Python 3.11, `device_configured: "cpu"`, `ffmpeg_available: true`, `ffprobe_available: true`, `models_directory_exists: true`, `llm_runtime_available: true`, `llm_weights_available: true`. Значение `full_protocol_implemented: false` ожидаемо: экспорт ещё не добавлен. Диагностика проверяет наличие файлов, но не запускает модели.

После подготовки запуск выполняется одной командой:

```powershell
.\scripts\run.ps1
```

Если PowerShell запрещает `.ps1`, **менять политику безопасности не требуется**. Эквивалентная команда:

```powershell
.\.venv\Scripts\python.exe -m autoprotocol.launch
```

Дождитесь сообщения Uvicorn о запуске и откройте **http://127.0.0.1:8000**. Команда запускает сервер и отдельный worker. Терминал должен оставаться открытым. Установка пакетов и скачивание моделей при обычном запуске не выполняются.

## Демонстрационный сценарий

### Собственная запись

Для первого прогона возьмите **MP3 или WAV на 30–60 секунд с двумя говорящими**. Используйте разрешённую к обработке запись; для публичной демонстрации реальные данные должны быть обезличены. Личные записи разработчика не включены в репозиторий и не требуются для запуска.

1. Откройте страницу приложения.
2. Введите название, например «Проверка жюри».
3. Укажите дату, если она известна; иначе оставьте поле пустым. Сегодняшняя дата не подставляется автоматически.
4. Оставьте `Asia/Almaty` или задайте подходящий IANA timezone, например `Asia/Qyzylorda`.
5. Выберите файл и подтвердите право обработки и уведомление участников.
6. Нажмите **«Загрузить и обработать»**.
7. Дождитесь этапов: очередь → подготовка аудио → распознавание → разделение говорящих → сопоставление.
8. При необходимости откройте встречу из списка **«Мои встречи»**.
9. Проверьте текст, метки говорящих и пометки исходной модели.
10. Нажмите таймкод реплики: плеер должен начать воспроизведение с этого момента.
11. В разделе **«Кто говорит»** введите известные имена и поставьте подтверждение для каждого заполненного имени.
12. При необходимости исправьте текст реплики и выберите говорящего. После прослушивания отметьте **«Реплика проверена по записи»**.
13. Нажмите **«Сохранить изменения»**. Дождитесь сообщения о сохранении и номере версии.
14. Обновите страницу и откройте встречу снова — имена и исправления должны сохраниться.
15. Раскройте **«Исходное распознавание»** у реплики и **«История сохранённых изменений»** под транскриптом, чтобы сравнить версии.
16. Нажмите **«Составить поручения и саммари»**. Пока есть несохранённые изменения, кнопка недоступна.
17. Дождитесь очереди и анализа: CPU может обрабатывать пример несколько минут. Закрытие страницы не отменяет работу worker.
18. Проверьте карточки поручений: действие, ответственный, исходный срок и статус. В разделе **«Источники в записи»** доступны точные цитаты и переходы по таймкодам.
19. Проверьте итоги по категориям «Факты», «Решения», «Поручения», «Открытые вопросы». Исправление исходного транскрипта требует нового запуска анализа.

Статус встречи **«Черновой транскрипт готов»** относится к STT/диаризации. У анализа отдельные состояния и сообщение **«Черновик готов»**. Сохранённые результаты переживают перезапуск; выгрузки протокола пока нет. Точного процента прогресса нет.

Пределы: **250 МиБ** (в интерфейсе подписано «МБ»), **10 минут**, одна обрабатываемая встреча за раз. Проверены MP3 и WAV. Интерфейс также принимает MP4/M4A/MKV/WebM/OGG/FLAC/AAC, но все контейнеры и видео не подтверждены отдельными прогонами. Для оценки используйте MP3/WAV.

Для LLM есть отдельный предел: 8192 токена контекста, не более 5700 токенов входа с системной инструкцией и схемой. Длинный текст отклоняется явно, не обрезается. Для первого анализа используйте 30–60 секунд. Имена исполнителей берутся из источников, а не автоматически из имени говорящего. Сложные сроки сохраняются текстом; календарная нормализация поддерживает только небольшой набор формулировок. Подтверждённые цитаты не гарантируют правильность смыслового вывода модели — все карточки остаются непроверенными.

### Ручная проверка и конфликт версий

Имя назначается только после вашего подтверждения. Чтобы снять имя, очистите поле и подтверждение, затем сохраните. Редактор позволяет выбирать голоса, обнаруженные в этой записи, включая кандидатов в спорных словах. Добавление нового голоса и объединение участников пока не реализованы.

Сохранение ручное: обновление страницы до нажатия кнопки может потерять черновые изменения. При уходе приложение запрашивает подтверждение; браузер может не показать предупреждение при принудительном закрытии процесса. После изменения текста или голоса отметка проверки реплики снимается до повторного подтверждения.

Если встреча изменена в другой вкладке, сохранение отклоняется с сообщением **«Сохранённая версия изменилась»**. Введённый текст остаётся в полях: скопируйте нужные правки, нажмите **«Загрузить сохранённую версию»**, внесите их заново и сохраните. Автоматического слияния изменений нет.

Исходные JSON, таймкоды, слова и пометки моделей не перезаписываются. Исправленный текст хранится отдельно; точные таймкоды отдельных слов относятся к исходному распознаванию. История доступна после перезапуска. Подробный контракт — [ручная проверка](docs/MANUAL_REVIEW.md).

### Синтетический пример без собственной записи

В репозитории есть текст и скрипт создания WAV локальным голосом **Microsoft Irina Desktop**. Нужен установленный русский голос Windows; он может отсутствовать на другом компьютере. Выполните в Windows PowerShell 5.1:

```powershell
.\scripts\synthesize_smoke.ps1
```

Загрузите полученный `data/smoke/ru.wav` через ту же форму. Исходный текст — [tests/fixtures/ru_smoke.txt](tests/fixtures/ru_smoke.txt). Это один синтетический голос: пример проверяет запуск, но не качество разделения нескольких людей и не казахскую речь. Если Irina отсутствует или скрипты запрещены политикой компьютера, используйте собственную короткую запись.

## Повторный запуск и остановка

После подготовки достаточно выполнить из корня репозитория:

```powershell
.\scripts\run.ps1
```

Остановка — **Ctrl+C** в терминале запуска. Сервер и дочерний worker завершаются; SQLite, оригиналы и готовые результаты остаются на диске. Закрытие вкладки браузера не останавливает обработку.

После прерывания worker восстанавливает задание по истечении lease (до 60 секунд), начиная проход заново. Допускается до двух попыток всего. Обычная ошибка модели приводит к `failed` без бесконечных повторов. После устранения ошибки обновите страницу и загрузите файл как новую встречу: отдельной кнопки повторной обработки пока нет.

### Если порт 8000 занят

Не требуется останавливать чужую программу. Выберите другой порт:

```powershell
$env:AUTOPROTOCOL_PORT = '8011'
.\.venv\Scripts\python.exe -m autoprotocol.launch
```

Адрес станет **http://127.0.0.1:8011**. Переменная действует в текущем терминале. Для постоянной настройки добавьте `AUTOPROTOCOL_PORT=8011` в локальный `.env`.

## Устранение проблем

| Симптом | Что сделать |
|---|---|
| `py` / `git` не найден | Установить инструмент и открыть новый терминал |
| Неподходящая версия Python | Проверить `py -3.11 --version`; нужен 3.11 x64 |
| `uv` не найден | Использовать `py -3.11 -m uv ...` после установки uv через этот Python |
| `.venv\Scripts\python.exe` отсутствует | Перейти в корень проекта и выполнить шаг 3 |
| Выполнение `.ps1` запрещено | Использовать прямые команды установки из шага 3 и `python.exe -m autoprotocol.launch` |
| FFmpeg/ffprobe не найден | Проверить обе команды `-version` в новом терминале; после изменения PATH перезапустить приложение |
| 401/403 при скачивании community-1 | Принять условия модели и войти в тот же аккаунт; при необходимости выполнить `.\.venv\Scripts\hf.exe auth login --force` |
| Загрузка весов прервалась | Проверить сеть и повторить соответствующий `prepare_*.py`; revision фиксирован |
| `OfflineModeIsEnabled` при подготовке | Для скачивания задать `$env:HF_HUB_OFFLINE='0'` в текущем PowerShell; inference сам включает offline-режим |
| «Локальные модели не найдены» | Повторить шаги 4–6; пустого каталога `models/` недостаточно |
| «Ошибка локального обработчика» | Проверить веса и свободную память; восстановить пакеты: `py -3.11 -m uv sync --frozen --extra stt --extra diarization` |
| Запись остаётся в очереди | Проверить терминал и отсутствие другой обрабатываемой встречи; запускать общий `autoprotocol.launch`, а не только Uvicorn |
| Превышен размер/длительность | Выбрать файл до 250 МиБ и 10 минут; увеличение настройки длительности не снимает предел текущего конвейера |
| «Не удалось прочитать запись» | Использовать исправный MP3/WAV с аудиодорожкой; простая смена расширения не исправляет файл |
| Таймаут этапа | Начать с 30–60 секунд; при необходимости увеличить `AUTOPROTOCOL_STAGE_TIMEOUT_SECONDS` в `.env` и перезапустить |
| `WinError 10048` / port already in use | Выбрать свободный порт по инструкции выше |
| `/health/ready` возвращает 503 | Ожидаемо для незавершённого полного протокола; проверить `/health/live` и загрузку |
| Реплики помечены как спорные | Прослушать: перекрытия, смена говорящего и неточные таймкоды намеренно не скрываются |
| «Подготовьте локальную LLM» | Выполнить шаг 7 и перезапустить общий launcher |
| Анализ постоянно в очереди | Перезапустить launcher после обновления проекта; старый worker не знает об очереди анализа |
| «Анализ не завершён» | Проверить модель, свободную RAM и более короткую запись; повторный клик после ошибки запускает новую попытку |
| Анализ устарел | Сохранённый транскрипт изменился: загрузить актуальную версию и повторить анализ |

Во **втором** терминале можно проверить доступность web-сервера:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health/live
```

Ожидается `status: ok`, `scope: web-server`. При другом порте измените адрес. Это проверка сервера, не качества моделей.

`/health/ready` намеренно возвращает 503 до реализации полного протокола с экспортом. Не используйте его как условие успешности демонстрации транскрипта и анализа.

## Проверки и фактические результаты

После установки зависимостей, из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\ruff.exe check src tests scripts
.\.venv\Scripts\ruff.exe format --check src tests scripts
```

Последний зафиксированный результат: **77 тестов прошли**, Ruff и форматирование без ошибок. Есть одно предупреждение Starlette об устаревании транспорта httpx в TestClient; оно не остановило тесты. Обычные тесты не скачивают модели и не запускают тяжёлый inference — реальные STT/диаризация и LLM проверяются отдельно.

Проверены ограничения загрузки, подтверждение обработки, дата/часовой пояс, повтор без дубля, очередь и восстановление lease, остановка процессов, миграция SQLite, отсутствие весов, сопоставление слов и говорящих.

Для редактора проверены сохранение после перезапуска, история старых/новых значений, неизменность исходного файла, конкурентные записи (200/409), отказ от чужих идентификаторов, атомарность правок, снятие имени и миграция старой БД. В Chrome проверены открытие редактора и ввод имени/текста; полный браузерный сценарий сохранения не завершён из-за остановки инструмента управления браузером.

Для LLM выполнены отдельные реальные прогоны на трёх синтетических текстах: изменение срока, отсутствие поручений с процитированной атакой на инструкции, отсутствие срока. Все три прошли заданные проверки на итоговом профиле; это не корпусная оценка. Анализ занял 38–134 секунды, максимальный измеренный RSS runtime — 3626,5 МиБ. Проверен также HTTP/worker-анализ ранее распознанной синтетической аудиозаписи и сохранность результата после перезапуска. Условия измерений и ограничения — в [отчёте фазы 4](docs/PHASE_4_REPORT.md).

| Прогон на Windows, CPU | Измеренный результат |
|---|---|
| Whisper, запись 274,25 секунды | 103,158 секунды; пик памяти процесса около 720 МиБ |
| community-1, та же запись | 227,287 секунды; пик около 2,3 ГиБ; 4 метки говорящих |
| Объединение полной записи | Все 573 слова сохранены; 68 фрагментов, 29 слов без говорящего |
| HTTP-проход 60 секунд записи | `queued → processing → ready`, 119 слов, 10 фрагментов |
| Аудио через HTTP Range | Ответ 206 с запрошенным диапазоном байтов |
| Синтетическая русская запись | Прошла API и worker до готового транскрипта |

Времена STT/диаризации включают загрузку моделей, но не скачивание весов и не все накладные расходы запуска. Это измерения конкретных прогонов, не обещание скорости на другом компьютере. Пиковая память относится к одному процессу.

**Ещё не подтверждены:** WER/CER и DER на размеченном корпусе, качество KK/mixed, полный прогон с отключённой внешней сетью, все видеоформаты, чистая установка на независимом компьютере жюри и полный визуальный браузерный тест. Реальный HTTP-конвейер проверен, но это не полная приёмка всего ТЗ.

## Архитектура и данные

```text
Браузер: загрузка, аудиоплеер, редактор транскрипта, поручения/саммари
    ↓ HTTP на 127.0.0.1
FastAPI + Jinja2 + локальные CSS/JavaScript
    ↓
SQLite: встречи, очередь, имена, ручные правки, история и снимки анализа
    ↓ отдельный worker, одна запись за раз
FFmpeg → Whisper → pyannote → сопоставление слов и говорящих
    ↓
Локальный JSON + нормализованное аудио → проверка в браузере
    ↓ по отдельной кнопке, из сохранённой версии
Qwen3-4B / llama.cpp → JSON и проверка цитат → поручения/саммари
```

ML-этапы выполняются отдельными процессами: память одной модели освобождается перед следующей. Inference использует локальные веса, отключает телеметрию Hugging Face/pyannote и автоскачивание. Код обработки не отправляет аудио и транскрипты в облачные API. Пакеты и модели скачиваются отдельно, на этапе подготовки; проверка изоляции на уровне ОС ещё предстоит.

Страница не использует CDN, внешние шрифты и аналитику. Сервер слушает только `127.0.0.1`; авторизации нет. Версия рассчитана на одного локального пользователя, а не на публичное размещение или общий сетевой доступ.

### Где находятся файлы

| Путь от корня | Содержимое |
|---|---|
| `.env` | Локальная конфигурация из `.env.example` |
| `.venv/` | Python и библиотеки |
| `models/faster-whisper-small/` | Веса STT |
| `models/pyannote-community-1/` | Веса диаризации |
| `models/qwen3-4b/` | Веса LLM, Apache-2.0 |
| `models/llama-b11124/` | Windows CPU runtime llama.cpp |
| `data/autoprotocol.sqlite3` | Метаданные, очередь, имена, исправления и история; рядом могут быть WAL/SHM-файлы |
| `data/meetings/<meeting_id>/source` | Загруженный оригинал под служебным именем |
| `data/meetings/<meeting_id>/<attempt_id>/` | WAV, промежуточные JSON и итоговый `result.json` |
| `data/smoke/` | Локальные тестовые файлы, создаваемые при прогонах |
| `data/analyses/<id>/<attempt>/` | Снимок сохранённого транскрипта и результат анализа; итог также хранится в SQLite |

Оригиналы, результаты, веса, `.env` и окружение исключены из Git. Остановка приложения их не удаляет; автоматическая очистка и кнопка удаления пока не реализованы. Для переноса готовой демонстрации нужно учитывать и SQLite, и файлы результатов — одной базы недостаточно.

### Настройки `.env`

| Переменная | Назначение |
|---|---|
| `AUTOPROTOCOL_DATA_DIR` | `data` — SQLite и записи |
| `AUTOPROTOCOL_MODELS_DIR` | `models` — веса |
| `AUTOPROTOCOL_DEVICE` | Оставить `cpu`; web-worker не поддерживает `cuda` |
| `AUTOPROTOCOL_PORT` | По умолчанию 8000; можно добавить 8011 или другой свободный порт |
| `AUTOPROTOCOL_MAX_UPLOAD_MB` | 250; единица в коде равна 1024² байт |
| `AUTOPROTOCOL_MAX_DURATION_MINUTES` | 10 в примере; фактически min(настройка, 10) |
| `AUTOPROTOCOL_STAGE_TIMEOUT_SECONDS` | 1800 на один этап |
| `AUTOPROTOCOL_FFMPEG` / `AUTOPROTOCOL_FFPROBE` | Необязательные пути к executable вместо поиска по PATH |

После изменений перезапустите приложение. Для первого запуска оставьте стандартные `data` и `models`: скрипты подготовки скачивают веса в `models/` репозитория независимо от пользовательского `AUTOPROTOCOL_MODELS_DIR`.

### API для технической проверки

| Метод и маршрут | Назначение |
|---|---|
| `GET /health/live` | Доступность сервера, 200 |
| `GET /health/ready` | Готовность полного протокола, пока 503 |
| `GET /api/meetings` | Последние 100 встреч |
| `POST /api/meetings` | Байты файла, `application/octet-stream`, метаданные в query; ответ 202 |
| `GET /api/meetings/{id}` | Статус, этап и ошибка |
| `GET /api/meetings/{id}/result` | Транскрипт с сохранёнными правками и версией; до готовности 409 |
| `GET /api/meetings/{id}/result?original=true` | Исходный JSON модели без ручных правок |
| `PATCH /api/meetings/{id}/result` | Имена/реплики с `expected_revision` и `source_digest`; конфликт — 409 |
| `GET /api/meetings/{id}/revisions` | Последние 100 сохранений с прежними и новыми значениями |
| `POST /api/meetings/{id}/analysis` | Поставить сохранённую версию в очередь; JSON: `expected_revision`, `source_digest` |
| `GET /api/meetings/{id}/analysis` | Статус/результат анализа и признак `stale` |
| `GET /api/meetings/{id}/audio` | WAV с Range; до готовности 409 |
| `GET /openapi.json` | Машиночитаемая схема API |

`/docs` и `/redoc` отключены, чтобы не загружать Swagger UI с CDN. Подробный контракт загрузки и восстановление описаны в [отчёте фазы 2](docs/PHASE_2_REPORT.md).
